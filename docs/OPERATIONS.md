# 운영 가이드 — 가용성 · 성능 · 데이터 보관

배포된 AI-SkinScope를 2026-12-10 성과 공유회까지 계속 동작시키기 위한 운영 절차입니다. 배포 구성은 [`Result.md`](Result.md) 5-1절, 시스템 구조는 [`AI_Skin_Scope_기술적용_매뉴얼.md`](AI_Skin_Scope_기술적용_매뉴얼.md)를 참고하세요.

## 1. 운영 구성과 위험 요소

| 구성 | 서비스 | 요금제 | 위험 요소 |
| --- | --- | --- | --- |
| 프론트엔드 | Vercel (`frontend/`) | 무료 | 정적 파일이라 위험 낮음 |
| 백엔드 | Render Web Service (FastAPI) | 무료 | **15분 동안 요청이 없으면 인스턴스가 꺼짐** → 다음 첫 요청이 깨어나는 시간만큼 느려짐(실측 약 49초) |
| DB | Render PostgreSQL | 무료 | **생성 30일 후 만료·삭제, 복구 불가**(10/12에 실제로 한 차례 만료) |
| AI | Google Gemini API | 무료 할당량 | 할당량 초과 시 보조 모델로 자동 전환(`gemini_fallback_model`) |

무료 요금제만으로는 "항상 켜져 있음"을 보장할 수 없습니다. 그래서 아래 2~4절의 **깨우기·점검·백업 절차**로 다운타임을 줄이고, 필요하면 5절의 유료 전환 기준을 따릅니다.

## 2. 가용성 — 서버 깨우기(웜업) 계획

> 현재 상태: **계획 단계(미설정)**. 성과 공유회 등 지속 운영이 필요할 때 아래 방법으로 설정합니다.

**방법**: 외부 무료 예약 호출 서비스(예: cron-job.org, UptimeRobot)가 백엔드 헬스 체크 주소를 **10분마다** 호출해 인스턴스가 꺼지지 않게 합니다. 공개 주소를 호출할 뿐이라 서버 권한이나 코드 변경은 필요 없습니다.

| 항목 | 값 |
| --- | --- |
| 호출 주소 | `https://ai-skinscope-team.onrender.com/health` |
| 주기 | 10분(꺼지는 기준 15분보다 짧게) |
| 실패 알림 | 연속 실패 시 담당자 이메일 알림 켜기 |
| 담당(설정 시) | 오주연(설정), 서경환(서버 확인) |

참고: Render 무료 인스턴스는 한 달 사용 시간 한도가 있으나, 서비스 1개를 계속 켜 두는 시간은 한도 안에 들어갑니다.

## 3. 정기 점검

| 주기 | 점검 | 방법 | 이상 시 |
| --- | --- | --- | --- |
| 매주 | 백엔드 상태 | 브라우저로 `/health` 접속 → 정상 응답 확인 | 서경환에게 알림, Render 로그 확인 |
| 매주 | 서비스 동작 | 휴대폰 데이터망으로 배포 주소 접속 → 사진 1장 분석 | 4절 장애 대응 |
| 매주(설정 후) | 깨우기 작동 | 예약 호출 서비스 실행 기록에서 실패가 없는지 확인 | 호출 주소·주기 재설정 |
| DB 생성일 + 25일 | DB 만료 대비 | 아래 4절 백업 후 새 DB 준비 | — |

## 4. 데이터 보관과 장애 대응

**백업 (DB 만료 대비)**

1. 만료 5일 전까지 `scripts/export_feedback.py`로 DB 기록을 CSV로 추출합니다.
   - ⚠️ 이 스크립트는 기본 출력 파일 `docs/user_test_results.csv`(1차 테스트 원본)를 **덮어씁니다.** 반드시 출력 파일명을 날짜를 넣어 바꿔 저장합니다(예: `backup_2026-11-05.csv`).
2. 백업 CSV는 개인정보 보호를 위해 **저장소에 올리지 않고** 팀 공유 드라이브에 보관합니다.
3. 새 DB를 만든 뒤 Render 백엔드 환경변수 `DATABASE_URL`을 새 주소로 바꾸고, `/health`와 분석·이력 화면으로 확인합니다.

**장애 대응 순서**

| 증상 | 원인 후보 | 조치 |
| --- | --- | --- |
| 첫 분석이 매우 느림(30초 이상) | 인스턴스가 꺼졌다 깨어남 | 1분 기다린 뒤 재시도, 지속 운영 시 깨우기 설정(2절) |
| 분석 실패·서버 오류 | Gemini 할당량, 서버 오류 | Render 로그 확인, 보조 모델 전환 여부 확인 |
| 이력이 모두 사라짐 | DB 만료 또는 `DATABASE_URL` 미설정(임시 SQLite에 저장) | 백업에서 복구, 환경변수 확인 |
| 화면이 안 뜸 | Vercel 배포 문제 | Vercel 대시보드에서 최근 배포 상태 확인 |

## 5. 성능 (NFR-01: 10초 이내)

| 측정 | 결과 | 원인 |
| --- | --- | --- |
| 첫 요청(인스턴스 꺼진 상태) | 약 49초 | 인스턴스가 깨어나는 시간 포함 |
| 인스턴스가 켜진 상태 | 약 18초 | Gemini 이미지 분석 + RAG 검색·임베딩 처리 |

- 2절 깨우기를 설정하면 **첫 요청 지연(약 49초)은 없앨 수 있습니다.**
- 켜진 상태의 약 18초는 AI 처리 시간이라 무료 구성에서는 NFR-01을 충족하지 못합니다. 개선 방향은 아래와 같고, 결과 보고서 7절에 한계로 기록했습니다.
  1. 분석 중 단계별 진행 안내를 보여 기다림 체감을 줄이기
  2. 임베딩 검색과 성분 추천처럼 서로 기다릴 필요 없는 단계를 동시에 처리(병렬화)
  3. 같은 요청의 참고 데이터 결과 캐시
  4. 유료 인스턴스 사용

## 6. 유료 전환 기준

다음 중 하나라도 해당하면 최저 요금제 전환을 팀에서 논의합니다(비용은 팀원이 나누어 부담하는 방안을 제안해 둔 상태).
