# AI-SkinScope 기능 요구 명세서

정리: 오주연(팀장) · 원안: 사전 프로토타입 단계의 팀 명세(2026-08-31) · 작성 시점: 2026-10 (턴 2)

## 1. 개요

- 프로젝트명: AI-SkinScope
- 목적: 스마트폰 카메라로 촬영한 얼굴 사진을 AI가 분석해 피부 상태 점수와 참고용 관리 가이드를 제공하고, 시간에 따른 변화를 추적하는 개인 피부 코칭 서비스
- 대상 사용자: 피부 트러블 상태를 스스로 판단하기 어려운 일반 대중
- 문서 범위: 기능·비기능 요구사항, 데이터 요구사항, AI 활용 명세, API, 시스템 아키텍처, 기술 스택 선정 이유, 검증 방법

## 4. 데이터 요구사항

| 결과물 (`app/data/`) | 원본 데이터셋 | 규모 | 관련 요구사항 |
| --- | --- | --- | --- |
| `age_gender_reference.json` | 한국인 피부상태 측정 데이터 | 1,072명, 연령대×성별 백분위 | FR-04, FR-13 |
| `region_reference.json` | 한국인 피부상태 측정 데이터 | 1,072명, 4개 부위 백분위 | FR-14 |
| `reference_measurements.json` | 한국인 피부상태 측정 데이터 | 300명 사진 임베딩 + 실측값 | FR-04 |
| `reference_embeddings.json` | 안면부 피부질환 이미지 합성데이터 | 5종 × 100장 임베딩 | FR-05 |
| `concern_ingredient_map.json` | 스킨케어 성분-효능 추천 데이터 | 9,000건, 8개 고민 | FR-24 |

## 5. AI 활용 명세

미션의 필수 기술 요소 5종 가운데 멀티모달 AI, RAG, AI Agent, Long-term Memory 4종을 사용합니다.

| 기능 | 기술 요소 | 상세 |
| --- | --- | --- |
| 피부 특징 추출 (FR-03, 04, 14) | 멀티모달 AI | Gemini Vision(`gemini-3.6-flash`, 실패 시 `gemini-3.5-flash-lite`)이 사진에서 6개 항목과 부위별 상태를 구조화된 JSON으로 추출 |
| 유사 증상 근거 (FR-05) | RAG ① | 사용자 사진을 `gemini-embedding-2`(768차원)로 임베딩 → 질환 이미지 인덱스에서 코사인 유사도 상위 5건 → 프롬프트에 근거로 주입 |
| 채점 근거 (FR-04) | RAG ② | 같은 임베딩으로 사진-실측값 인덱스에서 닮은 인물 상위 5명의 실측값 검색 → 백분위 기준과 함께 주입 |
| 챗봇 (FR-21) | RAG ③ + LLM | 질문 임베딩 → 지식베이스(성분 41 + FAQ 26)에서 유사 문서 검색 → 근거 기반 답변. 주 모델 쿼터 소진 시 대체 모델로 전환 |
| 상담 판단·병원 검색 (FR-06) | AI Agent | 분석 결과를 받아 다음 행동을 정하는 오케스트레이터. Gemini의 판단에 점수 임계값 규칙(40점 이하)을 더해 병원 방문 권장 여부를 정하고, 필요할 때만 카카오맵 검색 도구를 호출 |
| 이력·변화 추적 (FR-08, 09) | Long-term Memory | 사용자별 기록을 DB에 누적해 직전 기록과 비교 |
| 동년배 비교·피부나이 (FR-13) | 결정론적 계산 | Gemini를 다시 부르지 않고 연령대 통계와 사용자 점수를 비교해 계산. 같은 입력에 항상 같은 결과 |
| 이력분석 리포트 (FR-22) | 결정론적 계산 + LLM | 그래프는 저장된 기록만으로 추세(선형회귀) 계산. 그 추세를 근거로 텍스트 전용 Gemini 호출 1회로 관리 피드백 생성. 사용자가 버튼을 눌렀을 때만 호출 |
| 성분 추천 (FR-24) | 사전 분석 + 조회 | 성분-효능 9,000건을 미리 분석해 고민별 특이도 순위를 계산해 두고, 실시간에는 조회만 수행 |
| 자외선 지수 (FR-19) | 외부 API 연동 | 위치 좌표 → OpenWeatherMap 호출 → 지수·행동 요령으로 가공 |

### 안전 규칙

- 사진을 인식하지 못하면 점수를 내지 않고 재촬영을 안내합니다. 이 경우 병원 방문 권장도 하지 않습니다.
- AI가 병원 방문이 필요 없다고 판단해도 종합 점수가 40점 이하이면 방문 권장으로 올립니다(이중 안전장치).
- 모든 권고 문구 앞에 "AI 참고용 스크리닝이며 의료 진단이 아님"을 붙입니다.
- Gemini 호출이 모두 실패하면 추측한 결과를 내지 않고 오류(502)를 돌려줍니다.

## 7. 시스템 아키텍처

```text
[사용자 휴대폰 브라우저]

[Frontend: PWA (Vanilla JS) — Vercel]
   동의 → 촬영/업로드 (+ 나이·성별·위치 선택 입력)

        │

        │
        ▼
   Agent Service ──▶ 전문의 상담 판단 ──▶ 카카오맵 병원 검색 (필요할 때만)
        │              ├▶ 성분 추천 (사전 계산된 특이도 순위 조회)
        │              └▶ 피부나이·동년배 비교 (결정론적 계산)
        ▼
   Memory Service ──▶ DB (운영 PostgreSQL / 개발 SQLite)
        │
        ├──▶ Chat Service ◀── RAG ③ (지식베이스)
        ├──▶ Trend Analysis ──▶ 이력분석 리포트
        ├──▶ Share Service ──▶ 공유 링크
        └──▶ UV Service ──▶ OpenWeatherMap

[오프라인 준비 단계 — 턴 3]
   AI Hub 원본 (로컬) ──▶ scripts/build_*.py ──▶ app/data/*.json
```

## 8. 기술 스택 선정 이유

| 구분 | 선택 | 이유 |
| --- | --- | --- |
| AI 모델 | Google Gemini (Vision, Embedding) | 한 제공사에서 이미지 이해, 구조화된 JSON 출력, 이미지 임베딩을 모두 지원해 멀티모달 분석과 RAG를 같은 키로 구성할 수 있음. 무료 쿼터로 사용자 테스트 가능 |
| 대체 모델 | flash → flash-lite 자동 전환 | 테스트 중 쿼터 소진으로 서비스가 멈추는 것을 방지 |
| 백엔드 | FastAPI (Python) | 과정에서 배운 Python으로 AI 호출·데이터 처리를 한 언어로 구현. 타입 기반 스키마(Pydantic)로 AI 응답 형식을 검증 |
| RAG 저장소 | 사전 계산한 JSON 인덱스 + 코사인 유사도 | 참고 데이터가 최대 500건 규모라 벡터 DB 없이 메모리 검색으로 충분. 외부 인프라 의존을 줄여 배포가 단순 |
| DB | SQLAlchemy + PostgreSQL(운영) / SQLite(개발) | 같은 코드로 로컬 개발과 운영 배포를 모두 지원. 서버리스 환경에서도 이력이 유지되도록 운영은 호스팅 DB 사용 |
| 프론트엔드 | Vanilla JS PWA | 빌드 도구 없이 바로 배포. 앱 설치 없이 카메라 접근과 홈 화면 설치 가능 |
| 배포 | Vercel(프론트) + Render(백엔드) | 무료 구간에서 GitHub 연동 배포 가능. 정적 화면과 API 서버를 분리 |
| 외부 API | 카카오맵 로컬 검색, OpenWeatherMap | 국내 병원 검색 정확도, 무료 UV 지수 제공 |
